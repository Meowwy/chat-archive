# The Czech dictionary: where it comes from, and what you may do with it

The three data files in this folder are **not** covered by this repository's licence, and they
are **non-commercial**. Read this before reusing them anywhere else.

## The files

| file | rows | what it is |
|---|---|---|
| `words.txt` | 3,475,913 | every inflected Czech form, lowercased, sorted by UTF-8 byte order |
| `lemmas.txt` | 272,867 | the base forms; a line number here is a lemma id |
| `word-lemma.u24` | 3,475,913 x 3 B | one **big-endian** 24-bit lemma id per line of `words.txt` |

They are three parallel arrays: line *N* of `words.txt` belongs to the lemma named on line
*id* of `lemmas.txt`, where *id* is the *N*-th u24 in `word-lemma.u24`. Nothing records that
relationship except the line order, which is why `.gitattributes` pins these files to LF and
marks the `.u24` binary — a CRLF checkout would append `\r` to all 3.48M words and every lookup
past the first would quietly miss.

`app/archive/czech.py` compiles them into `Archives/czech_lemmas.sqlite`
(`py -m archive czech-dict`). That built file is derived data and is not committed.

## Provenance

Generated by the sibling project `czech_word_game`, which over-generates candidate forms with
hunspell and then filters them through a morphological analyser:

- **hunspell `cs_CZ`** — the stems and affix rules the forms were expanded from.
  [LibreOffice/dictionaries](https://github.com/LibreOffice/dictionaries/tree/master/cs_CZ).
  Licence: **GPL**.
- **LINDAT/ÚFAL MorphoDiTa** — used at build time via the public REST API
  (`/analyze?guesser=no`) to decide which of the 4.3M generated candidates are real Czech words,
  and to assign each form its lemma. It rejected 794,269 of them. Models are
  **CC BY-NC-SA 4.0** — <https://lindat.mff.cuni.cz/services/morphodita/>.
  No MorphoDiTa model or data file is redistributed here; only the analyser's verdicts shaped
  the output, and the share-alike and non-commercial terms are honoured on that basis.

  > Straková, Straka & Hajič. *Open-Source Tools for Morphology, Lemmatization, POS Tagging and
  > Named Entity Recognition.* ACL 2014.

## What that means in practice

**The `NC` is the binding constraint: this word list may not be used commercially.** This
archive is a personal, local, single-machine application, which is squarely inside those terms.
Going commercial would mean replacing the tagging oracle and regenerating the list from
scratch — the code in `czech.py` would not have to change, only the three files here.

Where a form is ambiguous (`ženu` is both *žena* and *hnát*) the upstream build already picked
one reading, the one whose own surface form is commonest. There is no context available at
search time, so that choice is inherited as-is.
